# 本地测试包与独立离线发码器

## 已确认的目标

用户要求开始封装为本地程序，在本地测试，并交付离线授权与发码程序。用户进一步选择：发码端做成可双击打开、带按钮的独立窗口，不再要求日常通过终端菜单操作。

已有产品使用 React + Tauri，已实现 Ed25519 离线机器绑定、每笔购买两个有效签发记录、加密保险库和中文 CLI。新工作复用这些经过测试的签发/校验规则，不另造一套许可证协议。

## 方案选择与实施判断

已向用户提供沿用中文终端菜单或独立窗口两种方式，用户选择独立窗口。CLI 保留为维护入口，但不是新的主要交付物。

实施判断：错题本继续使用 Tauri；商家发码器使用独立 Electron 应用，复用 `tools/license-admin/core.mjs`。相较把签发内核改写到 Rust，避免改变现有保险库格式及加密/名额逻辑；代价是发码器体积更大，需要独立更新其桌面运行时。发码器不进入买家的错题本安装包，两者不共享权限或应用目录。

本轮先交付当前这台 Intel Mac 可直接运行的两个本地程序；不自动推送、发布 GitHub Release 或生成 Windows/Apple Silicon 的“已实测”结论。保留原有三个平台的后续打包能力；其他目标需其对应构建和实机验证。

当前磁盘剩余约 1.5 GB，打包前要评估空间。仅可清理本任务工作区内可重新生成的构建缓存，不能删除用户题库、个人文件、已有保险库或唯一交付物；如果空间仍不足，明确报告并请用户腾出空间，不冒险继续生成不完整安装包。

## 两个独立程序

### 错题本（买家端）

- 保留全部当前功能、五款皮肤和最新 Logo/侧栏修复。
- 首次启动显示机器码、导出激活申请、导入授权和只读查看/导出。
- 正常发行包只嵌入公钥，不能包含卖家私钥、保险库、发码内核或测试题库。
- 授权永久离线校验，错误设备/篡改文件拒绝导入，失败不覆盖原授权。
- 未授权不能新增、编辑、评分、导入图片或正式 AI 识别，已有资料仍可查看导出。

### 错题本发码器（商家专用）

独立应用名与应用标识，内置自己的运行时；日常双击启动，不要求商家手动安装 Node 或打开终端。不启动 HTTP 服务、不联网、不加载远端脚本。

初始界面：创建加密保险库 / 打开已有保险库。创建需两次密码和明确确认；密码至少 12 位。保险库默认保存在仓库及应用安装目录之外，由商家选择；禁止把发码程序的自身资源目录作为保险库存放处。不静默覆盖已有保险库，不把私钥明文导出。

解锁后采用订单列表 + 当前订单设备详情的简单布局：

- 新建购买记录：订单备注、购买编号、已使用名额 0/2。
- 签发并导出：选择购买记录，粘贴机器码或通过系统选择激活申请文件，可填设备备注。
- 重新导出：同一设备返回已保存的原证书，不增加名额。
- 设备列表：显示已签发设备、机器码和签发时间；第三台不同设备明确拒绝。
- 人工换机：选择旧设备、新机器码、原因及二次确认；持续提示旧离线授权不能远程撤销，保留历史。
- 保险库操作：导出发行公钥、备份加密保险库、锁定退出；不提供明文私钥显示。

输出路径通过系统文件对话框选择。取消签发前的保存选择不占名额；证书必须先可靠记账再输出，输出写入失败可幂等重新导出。错误密码、损坏数据、写入失败显示中文可恢复提示，不重置账本。

密码仅在当前解锁过程中经受限 IPC 传到主进程，提交后清空输入，不持久化、不进入日志、参数或错误详情。私钥仅由主进程持有；前端只能得到脱敏的订单/设备信息和操作结果。退出/锁定释放保险库和文件锁。

## 安全边界

Electron 只加载打包的本地界面，关闭 renderer Node integration，启用 contextIsolation 和 sandbox，设置严格 CSP，拒绝窗口跳转/新窗口/非必要权限。主进程逐项暴露并校验业务 IPC，不暴露通用文件读写、shell、任意方法调用或原始 Electron 对象；验证消息发送方。

签发复用已有 AES-256-GCM + scrypt 加密、独占锁、原子保存及提交失败保护。GUI 适配不得绕过两设备上限或异常提交状态。不能同时在多份保险库备份上签发；恢复旧账本和手工换机不能远程撤销已签的离线证书。

## 测试包与正式密钥隔离

- 本地测试使用临时随机签发密钥及合成订单，不修改留空的正式公钥配置，不替用户生成正式生产私钥。
- 买家测试包使用独立应用标识、数据目录和明显的“本地测试版”名称，不能覆盖已有题库；测试证书仅用于本机检查，不适合对外售卖。
- 测试保险库/密码/签发材料不进入源码、普通买家包、安装资源、公共日志或 Git。测试结束后清理自动化临时秘密；任何需用户继续操作的测试材料明确标记其用途与保留位置，不能被误认为正式密钥。
- 正式售卖前，由用户在发码器窗口中亲自创建主保险库并输入自己的密码，离线备份后导出公钥，再以该公钥重新构建正式错题本。不会要求用户把密码或私钥发到聊天中。
- 未配置正式公钥继续阻止正式发行构建，不为方便打包而关闭验证。

## 本机验收

1. 所有现有前端、Node 签发器、Rust 校验及互操作测试通过；新 GUI 的解锁、创建订单、签发、幂等导出、第三台拒绝、换机和备份有自动化覆盖。
2. 打开实际封装的发码器，使用临时保险库走完整操作，重开后记录仍在；检查内置资源不包含保险库或测试秘密。
3. 打开实际本机错题本测试应用，检查全新数据、原生机器码、未授权只读路径、系统导出窗口、错误授权、有效授权、重开后保持激活、图片导入和原数据隔离。
4. 检查 Logo/侧栏动画在原生 WebView 中的效果。只把真实运行过的路径记为通过；原生窗口自动化受权限或环境限制时，列出需用户手测的项目，不以浏览器 IPC mock 代替真机结论。
5. 交付清楚命名的本机 `.app` 与可生成时的 `.dmg`、发码操作说明和本机测试报告。只作本地构建，不推送或发布；不改动用户个人题库。

## 非目标

不新增账号/支付/授权服务器/联网验证/自动更新，不承诺绝对防破解或实际离线运行设备永远只有两台，不撤销旧版本，不在本轮替用户配置 Developer ID、公证或购买证书。
