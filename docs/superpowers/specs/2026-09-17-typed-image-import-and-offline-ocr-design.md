# 题型化图片导入与离线 OCR 设计

## 目标

把拖入图片创建错题改造成完整、可恢复的导入流程：用户先决定多图如何分组，再为每一道题选择填空题、选择题或简答题；系统保存图片后在本机识别文字，按题型自动填入对应字段并等待用户校对。

本次只交付可测试的网页预览版本，不升级发布版本号，不生成桌面安装包，也不创建 GitHub Release。

## 设计原则

- 图片与识别内容只在本机处理，不上传到云端。
- 多图先分组、后选题型，避免题型或图片归属不明确。
- 用户确认题型后才创建错题；批量创建采用一次持久化写入，不留下半成品记录。
- OCR 只提取图片中已有内容，不自动解题或生成图片中不存在的答案。
- 识别结果是可编辑草稿，原图始终保留为最终依据。
- 旧数据自动兼容，已有错题和测试内容不得丢失。

## 用户流程

### 单张图片

1. 用户通过拖入、粘贴或文件选择导入图片。
2. 系统在内存中验证文件格式、大小和图片尺寸。
3. 显示题型选择对话框：填空题、选择题、简答题。
4. 用户确认后原子创建一道收集箱错题。
5. 自动进入收集箱并启动离线 OCR。
6. OCR 按题型自动填入字段，用户校对后保存并进入复习队列。

取消题型选择时不创建错题。

### 多张图片

1. 验证图片后显示带缩略图的分组对话框。
2. 用户选择：
   - 合为一题：全部图片形成一道题，然后选择一个题型。
   - 拆成多题：每张图片形成一道题，并分别选择题型。
3. 所有题型填写完成后，一次性保存全部错题。
4. 自动进入收集箱，定位到第一道新题，并依次启动 OCR。

关闭分组或题型对话框视为取消本次导入，不保存临时记录。连续导入请求进入队列，当前选择完成前不覆盖后续请求。

## 数据模型

新增题型：

```ts
type QuestionType = 'fill-blank' | 'choice' | 'short-answer'
```

`Mistake` 增加：

```ts
questionType: QuestionType
choice?: {
  mode: 'single' | 'multiple'
  options: Array<{ id: string; label: string; text: string }>
  correctOptionIds: string[]
}
fillBlank?: {
  blanks: Array<{ id: string; answer: string }>
}
shortAnswer?: {
  keyPoints: string[]
}
recognition?: {
  status: 'idle' | 'processing' | 'done' | 'error'
  confidence?: number
  reviewed: boolean
  message?: string
}
```

公共字段 `question`、`answer`、`cause`、`note`、`tags` 和 `images` 保留，以维持搜索、备份、列表和旧复习记录的兼容性。题型专属字段负责结构化交互；保存时同步生成公共 `answer` 文本，便于全文搜索与旧界面回退。

缺少 `questionType` 的旧错题在加载时迁移为 `short-answer`。迁移不提升 `notebook.json` 的顶层版本号，解析器以可选字段兼容旧数据；下一次保存时写入新字段。

## 导入架构

三个入口共用 `ImportController` 状态机：

1. `reading`：读取与验证文件。
2. `grouping`：多图选择合并或拆分；单图跳过。
3. `typing`：为每个图片组选择题型。
4. `saving`：调用 store 批量原子创建错题。
5. `recognizing`：进入收集箱后异步识别。
6. `complete` 或 `error`：反馈结果并处理下一条排队请求。

Tauri 桌面端继续使用 `onDragDropEvent` 获取真实文件路径，网页预览使用 DOM Drop API；两者都转换为 `ImageAsset[]` 后进入同一状态机。Store 新增批量创建操作，只在持久化成功后更新界面状态。

## 题型界面

题型选择采用标准居中对话框，使用既有墨蓝绿色视觉系统和 12px 以内圆角。三种题型以紧凑选项行呈现，明确说明创建后出现的字段。支持 Escape 取消、Tab 焦点循环和 Enter 确认；焦点进入时落在首个题型，关闭后回到导入按钮。

整理页根据题型渐进展示：

- 填空题：题干编辑器、空位列表、每个空位的答案输入。
- 选择题：题干、单选/多选模式、可增删和排序的选项、正确选项选择。
- 简答题：题干、参考答案、答题要点。

考试、科目、章节、错因、笔记、标签和图片区保持一致。题型可以在整理阶段修改；修改前提示会清理不兼容的结构化字段，但保留公共题干和答案文本。

复习页按题型提供不同作答方式：填空题逐空输入，选择题点击选项，简答题自由输入。揭示答案后仍使用现有四档反馈。

## 离线 OCR

继续使用 Tesseract.js 作为默认引擎，但把识别拆成可替换的 `OcrEngine` 与纯函数解析层，为以后更换本地模型保留接口。

### 预处理

识别只操作内存中的临时画布，不修改 `ImageAsset.dataUrl`：

1. 根据像素尺寸进行 1.5 至 2 倍放大。
2. 生成灰度增强和自适应阈值版本。
3. 检测有效内容边界并去除大面积空白。
4. 保留原图版本作为低对比度或彩色标记内容的回退。

### 多策略识别

- 对原图增强版和二值化版分别识别。
- 根据题型选择页面分割模式：选择题偏向多行块，填空题保留空格，简答题允许自动版面。
- 综合平均置信度、有效字符数和题型结构命中率选择最佳候选。
- 多图按图片顺序合并，并保留图片之间的段落边界。

### 结构解析

- 选择题：识别 `A.`、`B、`、`（C）` 等常见编号，拆分题干和选项；检测“答案/解析”区域。如果图片无答案，正确选项保持为空。
- 填空题：保留下划线、括号和方框等空位标记，生成对应空位；只在明确出现答案区域时填入答案。
- 简答题：按“答案、参考答案、解析、解”等标题分离题干与参考答案，并从分点文本生成答题要点建议。
- 中文标点、换行和多余空格进行保守清理，不自动改写公式或推断缺失内容。

低置信度结果显示“建议校对”，但不阻止保存。模型资源缺失、图片损坏或识别异常时，错题保持可编辑，并提供重新识别按钮与具体错误说明。

## 自动保存与并发

- 创建后先持久化原图和题型，再启动 OCR。
- 每识别完一张图片保存该图片的识别文本，全部解析完成后一次保存结构化字段。
- 用户已经修改过的字段不会被晚到的 OCR 结果覆盖；OCR 结果改为可选择合并。
- 连续导入请求串行进入选择流程，OCR 任务按题目执行，避免多个 Tesseract worker 争用内存。
- 应用重启时，处于 `processing` 的题目回到可重试状态，不自动重复写入。

## 错误与取消

- 混合文件导入时保留有效图片，并显示跳过数量及原因。
- 全部文件无效时不进入分组和题型步骤。
- 对话框取消时释放内存中的临时图片，不创建记录。
- 存储失败时保留当前对话框与选择结果，允许重试。
- OCR 失败不会回滚已成功创建的错题。
- 文件上限保持单文件 25 MB、单次 50 个；界面在进入识别前显示限制。

## 测试与验收

### 单元测试

- 导入状态机：单图、多图合并、多图拆分、连续请求、取消和失败重试。
- 数据兼容：旧错题迁移、题型字段验证、备份恢复和公共答案同步。
- OCR 纯函数：预处理尺寸、候选评分、选择题选项解析、填空标记解析、答案区域分离、中文清理。
- Store：批量原子创建、写入失败不更新 UI、OCR 不覆盖用户修改。

### 集成与人工测试

- 网页拖放、粘贴、文件选择行为一致。
- 桌面端在 macOS Finder 与 Windows 资源管理器中接收真实路径。
- 三种题型整理和复习交互正确。
- 模型缺失、模糊图片、混合文件、超大文件和连续拖入均有明确反馈。
- 键盘操作、焦点恢复、200% 缩放、中文长题干和 reduced motion 通过检查。
