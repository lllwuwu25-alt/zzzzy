# 永久离线设备授权

用户已选择并要求执行：纯本地、永久离线授权，一份购买授权最多签发两台设备，人工换机；不建设授权服务器。保留现有网页预览，当前不封装、发布或推送。

## 目标与方案

用户端机器码 → 人工发送给卖家 → 本地签发设备授权文件 → 用户离线导入。使用 Ed25519 签名而非客户端共享密码；私钥仅存在卖家工具的加密保险库，用户安装包只包含公钥。相比联网服务器方案，本方案不支持远程撤销；相比通用密码，复制授权到不同机器不能通过正常校验。

购买码不是签名私钥。卖家工具使用随机购买码记录订单，每笔订单最多两个有效签发记录；同一设备重复下载幂等，不占新名额。换机需指定原设备、填写原因并确认旧授权仍可离线使用；保留完整换机记录，不声称实际运行设备能严格限制为两台。

## 协议与信任边界

- v1 设备码：`CTB1-` 加 64 位 SHA-256 十六进制（展示时分组）。输入为产品域、平台与稳定系统标识；不使用用户名/MAC 地址，不发送原始系统标识。
- macOS 从 IOPlatformUUID 读取；Windows 从注册表 MachineGuid 读取（不启动可见控制台）；Linux 读取系统 machine-id。标识不可读时明确报错，不默默退化为通用设备码或随意随机码。
- 签名 envelope `{version:1,payload:<base64url JSON>,signature:<base64url64 bytes>}`；签名原文为 UTF-8 `mistake-notebook-license-v1\0` 与 payload 原字节拼接。
- payload 固定字段：schema=1、product=mistake-notebook、licenseId(UUID)、purchaseCode、deviceId(64位小写hex)、issuedAt(UTC ISO)、kind=perpetual、keyId(公钥 SHA256 前16位hex)。不加入到期时间或隐含升级期限。
- Rust 严格验证大小、字段、产品、设备、签名、签发公钥ID；不信任前端的“已激活”状态。授权文件单独保存在应用数据目录，不进入题库备份或工作区。
- 正式 release 构建必须配置有效的非零公钥；缺失时直接构建失败。开发构建仅在没有公钥时显示明确的开发状态；配置公钥后的 debug 构建也执行授权，便于测试。生产网页不伪装成已授权桌面版，Vite 开发网页保留预览体验。
- Rust 拒绝无授权的题库写入、图片导入及正式 AI 识别请求；读取/原题查看/导出始终允许。验证失败不覆盖已有有效授权，也不删除题目。

## 卖家本地工具

开发者判断：首版提供独立 Node.js 本地工具，中文菜单与 macOS/Windows 启动脚本，不启动 HTTP 服务、不联网，不进入用户安装包。所有密码通过无回显交互输入，不使用命令行参数或日志。初始化由用户自己执行并选择强密码；本次不自动创建生产私钥。

保险库保存私钥、订单、设备证书与换机历史，整体采用 scrypt(N=32768,r=8,p=1) 派生密钥、AES-256-GCM 加密，随机盐与每次写入的新 IV。使用单进程文件锁与临时文件、fsync、原子替换；必须先可靠保存签发记录再输出证书。重复请求可从记录找回原证书。密码遗失无法解密，应离线备份保险库和密码；禁止同时使用不同副本签发以免账本分叉。

## 用户体验

未激活界面提供机器码复制、导出申请、导入授权、明确错误与只读查看/导出入口。只读入口不能编辑、评分或导入；不会把用户资料加密扣留。授权成功进入原工作台；设置中显示购买编号、永久授权、设备码和重新导入入口。五种皮肤、键盘、窄屏与 reduced motion 保持可用。

## 边界与非目标

不能阻止修改程序/重新编译、完整系统克隆、离线旧授权继续使用、卖家恢复旧账本导致的历史丢失。不能让旧无授权版本自动失效。不上传题目或设备原始信息；不增加账号、订阅、支付系统、遥测或远程封禁。Windows/macOS 真机重装后的机器标识稳定性不能保证，失败走人工换机。

## 验收

Node 工具覆盖加密密码、两设备限制、幂等、换机、锁冲突、损坏账本、失败写入与证书找回。Rust 覆盖签名篡改、错设备/产品/公钥、超大文件、无授权写入防护与原授权保留，并执行 Node→Rust 的互操作验证。前端测试及隔离浏览器覆盖未激活→只读导出→导入失败/成功→刷新，确认授权不进入备份、网页预览不冒充正式激活。正式无公钥构建检查必须失败。生产私钥只由用户后续初始化，不能进入 Git 或 CI。
